# Weekend Gap Guard: a BNB Agent Studio agent whose trades go through GapGuardVault

The trading agent here was scaffolded with **BNB Agent Studio** (`@bnbagent/studio-cli` 0.0.15, the `bag` CLI). Its signing step is fixed code in the generated `signing.ts`. It uses Studio's `evm-local` wallet, and its only write is `GapGuardVault.buy()`. The vault decides whether the trade is allowed.

```
OBSERVE (read-only chain reads)  ->  DECIDE (decide.ts)  ->  EXECUTE (signing.ts: executeVaultBuy)
                                                              key = Studio getWallet() (evm-local keystore)
                                                              tx  = GapGuardVault.buy(token, usdt, memo)
```

## What is Studio-generated and what is ours

| Path | Origin |
| --- | --- |
| `gapguardagent/` (whole tree: `AGENTS.md`, `agentcore/`, `app/agent/src/{agentCard,executor,unifiedMain,sellerCore,model,tools,readToolCatalog,deliveryPolicy,requestLimits}.ts`, `studio.toml`, `.claude/skills/funding-pieverse-llm`) | **Generated by `bag init`**, unchanged |
| `app/agent/src/signing.ts`, top part (`signQuote`, `submitResult`, `settle`, ...) | **Generated by `bag init`**, unchanged |
| `app/agent/src/signing.ts`, bottom section marked `Weekend Gap Guard — added by our team` (`executeVaultBuy`) | **Ours.** Builds the `buy()` calldata, signs with Studio's `getWallet().signTransaction()`, broadcasts it, and decodes the vault's custom errors |
| `.studio/wallets/0x7099...79C8.json` (gitignored) | Created by **`bag wallet new --private-key -`** (Studio's own import), holding Hardhat dev account 1, the vault's `agent` |
| `app/agent/studio.toml` `[wallet].address` | Written by `bag wallet new` |
| `app/agent/src/gapguard/decide.ts` | **Ours.** The DECIDE step is a **deterministic stub** (see "Not done" below) |
| `app/agent/src/gapguard/demo.ts` | **Ours.** Runs the two-cycle demo |
| `app/agent/package.json` `"demo"` script and the `viem` dependency | Ours |
| `run-demo.js`, `package.json` (this folder) | Ours. The runner, plus a local (non-global) install of `@bnbagent/studio-cli` |

Studio sets the same rule we follow: signing happens only in fixed code (`signing.ts`) and is never offered to the LLM as a tool. The LLM can only ask for a BUY. GapGuardVault enforces the price-gap band, the daily limit, the whitelist and the freeze switch on-chain.

## Run it

Requirements: Node 22+ (tested with 24.12). pnpm runs through `npx pnpm@10.24.0`, with no global install.

```bash
cd studio-agent
npm install                                    # local bag CLI
cd gapguardagent && npx -y pnpm@10.24.0 install && cd ..

# one-time: import Hardhat dev account 1 (PUBLIC well-known test key, the vault's agent) into Studio's evm-local keystore
cd gapguardagent/app/agent
echo 0x59c6995e998f97a5a0044966f0945389dc9e86dae88c7a8412f4603b6b78690d \
  | WALLET_PASSWORD=gapguard-local-dev-only ../../../node_modules/.bin/bag wallet new --private-key - --save-password
cd ../../..

npm run demo
```

`npm run demo` works like this:
- If nothing is serving `http://localhost:5178/config.json`, it starts `../live/start.js` (Hardhat node on 8546, chainId 31337, with the contracts deployed) and stops it at the end.
- If `live/start.js` is already running, it reuses it. It sends `POST /reset` (a fresh deploy) before the run, and again after, so the shared server is left in its initial state.

## Not done (and why)

- **LLM decision.** The Studio default LLM is Pieverse `auto/free` ($0/token). It needs `bag llm activate` first, which does a SIWE login with the agent wallet and creates a Pieverse API key on an external service. We did not do that with a publicly known dev key. Until then, `decide.ts` uses a **clearly labelled deterministic momentum stub** (`source=deterministic-stub` in the output). An LLM path through the generated `buildModel()` exists behind `GAPGUARD_LLM=1`, but it is **untested**. To enable it, use a fresh wallet that belongs to you: run `bag llm activate`, then `GAPGUARD_LLM=1 npm run demo`.
- **`bag deploy` and ERC-8004 registration (`bag erc8004 register`).** These need a wallet funded with tBNB on BSC testnet (`bag doctor` asks for ≥ 0.02 tBNB; get it from the Telegram faucet bot), plus a deploy target (AWS credentials, or the BNB managed trial via `bag platform login`). The user has to do this with their own throwaway testnet wallet. **Never register the Hardhat dev key**: it is public.
- **GapGuardVault on BSC testnet.** It only runs on the local Hardhat chain. The Studio project's `[network].default` is still `bsc-testnet` (that is what Studio scaffolds), and the vault RPC/chainId (`http://127.0.0.1:8546`, 31337) is passed to `executeVaultBuy` explicitly.
- **The generated seller faces (A2A / x402 via `bag dev`).** Not used by this demo. The scaffold is a *seller* agent (ERC-8183 jobs, x402 payments), and `bag doctor` FAILs the x402 rail until B402 merchant credentials exist. We use the scaffold's wallet, signing module and model factory, but not its HTTP server.
